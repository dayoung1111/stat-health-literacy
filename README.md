## 1. 프로젝트 개요

**한 줄 소개**
알려 주는 앱이 아니라, **알았는지 확인하는 앱**이다. 병원 안내문을 누구나 이해할 수 있게 바꾸고, 티치백(teach-back)으로 이해 여부를 확인해 기록으로 남긴다.

> "네, 알겠습니다"를 진짜 이해로 바꾸는 병원용 환자교육 도구

**왜 병원에 필요한가**

| 병원이 겪는 문제 | S.T.A.T 도입 후 |
|---|---|
| 금식·장정결제 복용을 잘못 이해해 검사가 미뤄지거나 취소됨 | 핵심 안전 항목을 티치백으로 확인해 검사 전 오해를 잡아낸다 |
| 간호사가 같은 설명을 환자마다 처음부터 반복함 | 쉬운 안내는 앱이 맡고, 간호사는 환자가 틀린 부분만 다시 설명한다 |
| "설명했다"는 기록은 있어도 "이해했다"는 근거는 없음 | 티치백 결과가 남아 환자교육의 질과 환자안전을 확인할 수 있다 |
| 통역·수어 지원이 모든 시간, 모든 병원에 있지 않음 | 쉬운 말·그림·큰 글씨·다국어를 한 화면에서 함께 제공한다 |

**누구를 위한 앱인가**
- **구매·도입 주체 — 병원**: 환자안전과 환자교육의 질을 관리해야 하는 의료기관
- **사용자 — 간호사**: 짧은 시간에 많은 환자를 교육해야 하는 현장 간호사
- **수혜자 — 환자**: 고령자·장애인·아동·외국인을 포함해, 아프고 불안한 상황에서 병원 문서를 이해하기 어려운 모든 사람

**어떤 상황에서 쓰는가**
1. 간호사가 외래·병동에서 환자에게 필요한 안내 영역(일반검사·내시경·복용약)을 골라 교육 코드를 발급한다.
2. 환자는 대기 중이나 귀가 후 코드와 생년월일만으로 안내를 열어 자기 속도로 다시 본다. 앱 설치는 필요 없다.
3. 안내를 본 뒤 티치백 질문(예: "몇 시부터 물을 마시면 안 될까요?")에 답한다. 틀리면 다른 표현으로 다시 설명하고 다시 묻는다.
4. 간호사는 결과 화면에서 환자가 이해하지 못한 항목만 확인해 짧게 보충 설명한다.
   
### 기획 의도

병원은 하루에도 수많은 문서를 건넨다. 대장내시경 전 안내문, 복약안내서, 입·퇴원 준비 안내문은 치료의 시작이자 안전의 조건이다. 같은 문서가 누군가에게는 한 번 읽으면 충분한 안내이지만, 고령자·장애인·아동·외국인에게는 넘기 어려운 벽이 된다. 금식 시간을 잘못 이해해 검사가 미뤄지고, 복용 시간을 혼동해 치료 효과를 잃는다. 이는 개인의 부주의가 아니라 정보 접근의 불평등에서 비롯된다. **건강문해력의 격차는 곧 건강형평성의 격차이다.**

우리는 간호학도로서 이 문제를 '환자가 이해하지 못한 것'이 아니라 **'우리가 이해시키지 못한 것'** 으로 바라보았다. 팀에는 장애인복지 현장에서 5년간 일한 팀원이 있다. 그는 설명이 조금만 쉬웠다면 스스로 할 수 있었던 일을 포기하는 사람들을 가까이에서 지켜보았다. 그 경험이 우리에게 질문을 남겼다. *"좋은 설명은 누구에게나 닿을 수 있는가?"*

의료 현장에서 **STAT**은 '즉시'를 뜻한다. S.T.A.T는 이해가 필요한 바로 그 순간에 누구도 뒤처지지 않도록 돕는다.

**왜 병원이 사용 주체인가** — 정보 취약계층일수록 스스로 앱을 찾아 설치하기 어렵다. 도움은 그들이 찾아오기를 기다려서는 안 되며, 그들이 이미 서 있는 자리, 곧 진료 현장에서 건네져야 한다.

| 대상 | S.T.A.T가 제공하는 가치 |
|---|---|
| 환자 | 이해와 안심 |
| 의료진 | 교육의 질 향상, 반복 설명 시간 절감 |
| 병원 | 환자안전과 신뢰 |

**설계 원칙** — S.T.A.T는 개인정보가 아닌 **보편적 설명과 접근성**에 집중한다. 환자 이름·등록번호·전화번호를 저장하지 않으며, 기술이 사람을 가르는 도구가 아니라 사람을 잇는 다리가 되도록 설계하였다.

## 2. 주요 기능

| 과제의 꼭 있어야 하는 기능 | 화면(프론트엔드) | API(백엔드) |
|---|---|---|
| 1. 병원 안내문을 이해하기 쉬운 형태로 제공 | 환자 화면: 쉬운 말·그림·큰 글씨·다국어 전환 안내 페이지 | 교육 코드에 연결된 안내 항목 조회 |
| 2. 티치백으로 이해 여부 확인 | 환자 화면: 안내 후 핵심 내용을 다시 설명·선택하는 티치백 단계, 복용약 체크 | 티치백 결과·체크한 복용약 저장 |
| 3. 의료진이 환자별 안내를 지정하고 결과 확인 | 간호사 화면: 검사 영역(일반검사·내시경·복용약) 지정, 교육 코드 발급, 티치백 결과 확인 | 교육 코드 생성(생년월일 암호화 저장), 결과 조회 |

**더 만든 기능**
- 관리자 화면: 의료진 로그인 화면을 공유하되 관리자 아이디로 로그인하면 관리자 화면으로 이동
- 이해하지 못한 항목 표시: 티치백에서 틀린 부분을 간호사가 바로 확인해 그 부분만 다시 설명

## 4. 실행 방법

자세한 환경 설정은 [`docs/SETUP.md`](docs/SETUP.md)를 따른다.

```bash
# 1. 저장소 내려받기
git clone https://github.com/dayoung1111/stat-health-literacy.git
cd stat-health-literacy

# 2. 패키지 설치
npm install

# 3. 환경 변수 설정 (.env.example을 복사해 Supabase 주소와 키 입력)
cp .env.example .env

# 4. 개발 서버 실행
npm run dev
```

## 6. 팀원 역할

(이름·학번 없이 역할만)

- **기획**: 문제 정의(건강문해력·건강형평성), 장애인복지 현장 경험을 바탕으로 한 접근성 기준 설정, 안내 콘텐츠 구성
- **프론트엔드**: 환자용 화면(안내·티치백), 보건관리자용(간호사용) 화면(검사 영역 지정·코드 발급·결과 확인)
- **백엔드**: Supabase DB 설계, 교육 코드 발급·생년월일 암호화, 결과 저장·조회
- **검증**: 안내 내용의 간호학적 정확성 검토, 시연 시나리오 테스트

## 7. 아쉬운 점과 다음에 할 일

**아쉬운 점**
- 해커톤 기간 내 구현하여 안내 영역이 대장내시경·복용약 중심에 머물렀다.
- 실제 정보 취약계층 대상자에게 사용성 평가를 받지 못했다.
- 다국어 안내의 번역 품질을 의료 통역 전문가에게 검토받지 못했다.

**다음에 할 일**
- 입·퇴원 준비, 수술 전 안내 등 안내 영역 확대
- 음성 읽어주기(TTS)와 수어 영상 등 감각장애인을 위한 접근성 강화
- 발달장애인을 위한 이지리드(Easy Read) 기준 적용
- 테스트용·운영용 DB 분리 및 병원 정보보호 기준에 맞춘 보안 점검
- 티치백 결과를 모아 자주 오해하는 항목을 분석하고 안내문 개선에 반영
