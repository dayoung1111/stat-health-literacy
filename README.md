## 1. 프로젝트 개요

**한 줄 소개**
알려 주는 앱이 아니라, **알았는지 확인하는 앱**이다. 병원 안내문을 누구나 이해할 수 있게 바꾸고, 티치백(teach-back)으로 이해 여부를 확인해 기록으로 남긴다.

> "네, 알겠습니다"를 진짜 이해로 바꾸는 병원용 환자교육 도구

**왜 병원에 필요한가**

병원은 시술과 진료 전후마다 안내문을 건넨다. 검사 전 준비 사항, 복약 방법, 시술 후 주의할 점까지 환자가 집에서 스스로 지켜야 할 내용이 대부분이다. 문제는 안내문을 건네는 것과 환자가 그 내용을 이해하는 것 사이에 간격이 있다는 점이다. S.T.A.T는 **"이 안내문을 어떻게 하면 환자가 제대로 이해할 수 있을까?"** 라는 현장의 질문에서 출발하였다.

| 현장에서 겪는 어려움 | S.T.A.T가 바꾸는 것 |
|---|---|
| 시술·진료 전후 안내문을 받아도, 환자가 무엇을 언제 해야 하는지 정확히 알지 못한 채 귀가한다 | 안내문의 핵심을 쉬운 말과 그림으로 다시 보여 주고, 꼭 지켜야 할 내용은 티치백으로 한 번 더 확인한다 |
| 외래·병동의 바쁜 흐름 속에서 간호사가 환자마다 같은 설명을 처음부터 반복한다 | 기본 안내는 앱이 맡고, 간호사는 환자가 헷갈려한 부분에 집중해 설명한다 |
| "설명했다"는 기록은 남지만, 환자가 실제로 이해했는지는 확인하기 어렵다 | 티치백 결과가 남아 누가 어떤 내용을 이해하지 못했는지 바로 알 수 있다 |
| 고령자·외국인·장애인에게 필요한 통역이나 별도 자료가 늘 준비되어 있지는 않다 | 큰 글씨·그림·다국어 안내를 한 화면에서 함께 제공해, 따로 준비하지 않아도 누구나 같은 안내를 받는다 |

**누구를 위한 앱인가**
- **구매·도입 주체 — 병원**: 환자안전과 환자교육의 질을 관리해야 하는 의료기관
- **사용자 — 간호사**: 짧은 시간에 많은 환자를 교육해야 하는 현장 간호사
- **수혜자 — 환자**: 고령자·장애인·아동·외국인을 포함해, 아프고 불안한 상황에서 병원 문서를 이해하기 어려운 모든 사람

**어떤 상황에서 쓰는가**
1. 간호사가 외래·병동에서 환자에게 필요한 안내 영역(일반검사·내시경·복용약)을 골라 교육 코드를 발급한다.
2. 환자는 대기 중이나 귀가 후 코드와 생년월일만으로 안내를 열어 자기 속도로 다시 본다. 앱 설치는 필요 없다.
3. 안내를 본 뒤 티치백 질문(예: "몇 시부터 물을 마시면 안 될까요?")에 답한다. 틀리면 다른 표현으로 다시 설명하고 다시 묻는다.
4. 간호사는 결과 화면에서 환자가 이해하지 못한 항목만 확인해 짧게 보충 설명한다.

### 기획 의도

병원은 하루에도 수많은 문서를 건넨다. 대장내시경 전 안내문, 복약안내서, 입·퇴원 준비 안내문은 치료의 시작이자 안전의 조건이다. 같은 문서가 누군가에게는 한 번 읽으면 충분한 안내이지만, 고령자·장애인·아동·외국인에게는 넘기 어려운 벽이 된다. 금식 시간을 잘못 이해해 검사가 미뤄지고, 복용 시간을 혼동해 치료 효과를 잃는다. 이는 개인의 부주의가 아니라 정보 접근의 불평등에서 비롯된다. **건강문해력의 격차는 곧 건강형평성의 격차이다.**

우리는 간호학도로서 이 문제를 '환자가 이해하지 못한 것'이 아니라 **'우리가 이해시키지 못한 것'** 으로 바라보았다. 팀에는 장애인복지 현장에서 5년간 일한 팀원이 있다. 그는 설명이 조금만 쉬웠다면 스스로 할 수 있었던 일을 포기하는 사람들을 가까이에서 지켜보았다. 그 경험이 우리에게 질문을 남겼다. *"좋은 설명은 누구에게나 닿을 수 있는가?"*

의료 현장에서 **STAT**은 '즉시'를 뜻한다. S.T.A.T는 이해가 필요한 바로 그 순간에 누구도 뒤처지지 않도록 돕는다.

**왜 병원이 사용 주체인가** — 정보 취약계층일수록 스스로 앱을 찾아 설치하기 어렵다. 도움은 그들이 찾아오기를 기다려서는 안 되며, 그들이 이미 서 있는 자리, 곧 진료 현장에서 건네져야 한다.

| 대상 | S.T.A.T가 제공하는 가치 |
|---|---|
| 환자 | 이해와 안심 |
| 의료진 | 교육의 질 향상, 반복 설명 시간 절감 |
| 병원 | 환자안전과 신뢰 |

**설계 원칙** — S.T.A.T는 개인정보가 아닌 **보편적 설명과 접근성**에 집중한다. 환자 이름·등록번호·전화번호를 저장하지 않으며, 기술이 사람을 가르는 도구가 아니라 사람을 잇는 다리가 되도록 설계하였다.

## 2. 주요 기능

| 과제의 꼭 있어야 하는 기능 | 화면(프론트엔드) | API(백엔드) |
|---|---|---|
| 1. 병원 안내문을 이해하기 쉬운 형태로 제공 | 환자 입장(`/p`) → 홈 "지금 할 일"(`/p/코드/home`) → 쉬운 안내문(`/guide`), 또박이 사진 수업(`/video`), 위험 신호(`/danger`), 복용약(`/medication`) | `enterPatient`(코드·생년월일 확인, 5회 실패 잠금), `translateForPatient`(Claude API 다국어 번역, 숫자 보존 검사), `recordConfusion`("헷갈려요" 기록) |
| 2. 티치백으로 이해 여부 확인 | 티치백 화면(`/p/코드/check`): 3문제, 틀리면 다른 표현으로 다시 설명 후 재질문 | `recordTeachback`(정답 여부 저장), `saveMyMedications`·`recordMedicationQuiz`(복용약 체크·확인 문제 저장), `completeGuide`(안내 완료 기록) |
| 3. 의료진이 환자별 안내를 지정하고 결과 확인 | 의료진 로그인(`/staff`) → 코드 발급(`/staff/new`) → 발급 완료·QR(`/staff/issued/코드`) → 내 코드 목록·결과 상세(`/staff/codes`) → 관리자(`/staff/admin`) | `loginStaff`·`logoutStaff`(의료진 로그인), `issueCode`(교육 코드 발급, 생년월일 해시 저장, 7일 만료) |

**더 만든 기능**

| 기능 | 내용 |
|---|---|
| 또박이 선생님 수업 | 캐릭터 '또박이'가 대장내시경 준비(1~8교시), 검진 전날 준비, 복용 중인 약을 사진 수업 영상으로 차례대로 설명하고 깜짝 퀴즈를 낸다. 복용약 수업은 환자가 고른 약에 맞는 장면만 보여 준다. 글을 읽기 어려운 환자도 보고 들으며 따라갈 수 있다. |
| 사진·그림 안내 | 먹어도 되는 음식과 피해야 할 음식, 약 복용, 금연, 보호자 동반 등 중요한 행동을 실제 사진과 그림 카드로 보여 준다. |
| "헷갈려요" 버튼 | 이해되지 않는 문장에서 버튼을 누르면 더 쉬운 표현으로 다시 설명한다. 누른 기록은 간호사가 확인할 수 있다. |
| 지금 할 일 | 검사일을 기준으로 오늘 환자가 해야 할 일만 골라 홈 화면에 보여 준다. |
| 위험 신호 안내 | 바로 병원에 연락해야 하는 증상을 따로 강조하고, 누르면 병원으로 바로 전화가 연결된다. |
| 5개 언어 지원 | 한국어·영어·일본어·중국어·베트남어로 안내를 볼 수 있다. 번역 후 시간·용량 숫자가 원문과 같은지 자동으로 확인하고, 다르면 번역을 쓰지 않는다. |
| QR 코드 발급 | 간호사가 발급한 교육 코드를 QR 코드로 보여 주어, 환자가 휴대폰 카메라로 바로 열 수 있다. |
| 관리자 화면 | 의료진 로그인 화면을 함께 쓰되, 관리자 아이디로 로그인하면 관리자 화면으로 이동한다. |
| 개인정보 보호 | 이름·등록번호·전화번호를 받지 않고, 생년월일은 암호화해 저장한다. 5번 틀리면 잠기고 코드는 7일 뒤 만료된다. |

## 3. 기술 스택

- **프론트엔드**: Next.js 16(App Router), React 19, TypeScript, Tailwind CSS 4
- **백엔드**: Next.js 서버 기능(Server Actions), Prisma 7(DB 연결), Claude API(Claude Haiku, 안내문 다국어 번역)
- **데이터(어디에, 무엇을)**: Supabase PostgreSQL(서울 지역) 시연용 DB 하나에 교육 코드·고른 안내·암호화한 생년월일, 환자가 체크한 복용약, 티치백 결과를 저장한다(환자 이름·등록번호·전화번호는 저장하지 않음). 실제 환자에게 쓸 때는 테스트용과 운영용 DB를 분리한다.

## 5. AI 활용 내역

- **사용한 도구**: Claude Code (화면·기능 코드 작성), Claude API (앱 안에서 안내문 다국어 번역)

- **주요 프롬프트(그대로 붙여 넣기)**

**■ 또박이 캐릭터 제작**

**① 콘셉트 설정**

```text
환자한테주는 그 종이가 너라고 생각하면 되지않을까?
```

→ 환자가 받는 종이 안내문이 직접 말을 걸고 설명해 주는 '질문할 수 있는 안내문'이라는 콘셉트를 정하였다.

**② 캐릭터 디자인**

```text
이 어플이랑 어울리는 캐릭터만들어줘
```

→ 종이 안내문이 살아난 캐릭터 '또박이'를 만들었다. 접힌 귀퉁이와 글줄은 안내문을, 초록 십자는 병원에서 온 믿을 수 있는 정보를 뜻한다. 장면에 맞춰 인사·설명·시간 알림·칭찬·주의의 다섯 가지 표정을 두었다.

**③ 수업 영상으로 확장**

```text
이런식말고 또박이가 강의하는 느낌이면 좋겠는데
```

→ 그림 카드를 나열하는 방식 대신, 또박이가 선생님이 되어 장면마다 설명하고 교시 끝에 돌발 퀴즈를 내는 '또박이 선생님 수업' 형식으로 바꾸었다.

**④ 접근성 판단**

```text
또박이가 수어하는건 못만들지?
```

→ 수어는 손 모양과 표정까지 포함한 독립된 언어이므로, 캐릭터가 수어를 흉내 내면 잘못된 정보를 줄 수 있다고 판단하였다. 따라서 또박이는 수어를 하지 않고, 검증된 수어 영상을 함께 보여 주는 방식으로 설계하였다.

**■ 데이터 저장 문제 해결**

**① 번호 발급 오류 → DB 저장으로 변경**

```text
배포 사이트에서 의료진이 번호를 발급하면 오류가 나거나 기록이 사라져.
원인: src/lib/education-store.ts가 서버 메모리(Map)에 저장해서 Vercel 여러 서버끼리 공유가 안 됨.
.env에 DATABASE_URL과 DIRECT_URL을 넣었어 (Supabase, 서울 지역).
.env 내용과 키 값은 절대 화면에 출력하거나 읽어서 보여 주지 마.

해 줘:
1. education-store.ts의 모든 저장·조회를 Prisma(src/lib/db.ts의 getDb)로 바꿔서 Supabase에 저장되게.
함수 이름과 화면 동작은 그대로, 보안(생년월일 해시, 5번 잠금, 7일 만료, 남의 코드 404)도 그대로.
2. schema.prisma에 없는 칸(guideCompletions 등)이 있으면 추가하고 마이그레이션 실행. Prisma 8로 올리지 말 것.
3. 시연 코드(000000, 482917, 예시 코드들)는 DB에 없을 때만 한 번 넣기 (중복 생성 X).
4. 시연용 새 코드 777777 (생년월일 111111) 추가: 건강검진 기본 + 대장내시경 + 위내시경 + 드시는 약 전부 묶기.
위내시경은 아직 내용이 없으니 지금처럼 "준비 중"으로 보이면 돼.
5. 확인: 발급 → 다른 창에서 환자 입장 → 결과가 의료진 목록에 남는지, 서버 껐다 켜도 남는지 테스트.
npm run check, npm test, npm run build 통과 (SESSION_SECRET은 임시 값으로 실행하고 파일에 저장하지 말 것).
6. DB가 서울에 있으니 Vercel 서버 지역도 서울(icn1)로 맞추는 게 좋은지 확인하고, 필요하면 설정해 줘 (반응속도 점수).
7. Vercel에 넣어야 할 환경변수 이름만 알려 줘 (값은 말하지 말고).
8. plans 파일에 [찾은 문제 / 요청 원문 / 바꾼 결과]로 기록하고 main에 커밋. push는 내가 할게.
```

→ 발급 번호와 티치백 결과, 5번 잠금, 안내 완료 기록을 서버 메모리가 아닌 Supabase DB에 저장하도록 바꾸었다. 서버가 바뀌거나 다시 켜져도 기록이 남고, 다른 사람도 같은 번호로 들어올 수 있게 되었다. 서버 지역을 서울로 맞춰 응답 속도를 높였다.

**■ 검진 전날·복용약 또박이 수업 제작**

**① 새 수업으로 확장**

```text
이 내용을 또박이 영상처럼 만들어주는데 일단 예시부터 보여줘
```

```text
복용 중인 약이 있는 경우 … 이 내용을 또박이 영상처럼 만들 거야
```

→ 대장내시경 수업과 같은 형식(가로 16:9, 오른쪽 또박이, 아래 흰 말풍선 자막, 빨간 X·초록 동그라미, 깜짝 퀴즈)으로 '검진 전날 준비'와 '복용 중인 약' 수업 시안을 만들었다. 복용약 수업은 환자가 먹는 약을 고르면 그 약에 맞는 장면과 퀴즈만 나오도록 하였다.

**② 읽기 쉬운 자막과 원래 또박이**

```text
영상에 나오는 문장을 이상하게 띄우지 말고 긴 문장으로 이어져서 나오게 해줘. 그리고 또박이 그림체를 처음 만들어진 대장내시경 안내 영상 속의 또박이처럼 둥글고 귀여운 느낌으로 바꿔줘
```

```text
몸뚱이 길이가 지금보다 짧아
```

→ 색칠한 핵심 단어도 문장 안에 자연스럽게 이어지게 하고, 한국어 단어가 중간에 잘리지 않게 하였다. 원본 그림을 기준으로 또박이를 짧고 통통한 몸, 왼쪽 위 접힌 귀퉁이, 가는 선으로 다시 맞추었다.

**③ 헷갈리지 않는 그림**

```text
혈압약이랑 당뇨약은 다르게 생겼는데 크게 보이는 이미지가 너무 똑같아서 보는 사람 입장에서 두 화면의 차이를 이해하기 힘들 수도 있을 것 같아. 그리고 물 조금이라는 부분을 이해하기 쉽도록 컵의 1/4 정도만 담긴 이미지로 바꾸고 싶어
```

→ 약마다 모양·색과 질환 표시(혈압계 바늘, 하트, 각설탕, 핏방울)를 다르게 그렸다. '물 조금'은 1/4만 찬 컵, '처방한 의사'는 가운과 청진기를 한 의사, '모르는 약'은 알약 위 물음표로 바꾸었다.

**④ 실제 사진과 균형 잡힌 화면**

```text
무거운 운동, 오래 달리기 부분을 사람이 행동하는 모습으로 바꿔줘
```

```text
화면 배열이 균형적이었으면 좋겠어. 지금은 다 한쪽으로 치우친 느낌?
```

```text
튀긴 음식, 기름진 고기를 한 묶음으로 묶어서 기름진 음식으로 바꾸고 … 내가 보낸 이미지로 바꿔줘. 사물이 잘 보이게
```

→ 팀이 만든 사진 12장으로 그림을 바꾸고, 음식이 접시 가운데 꽉 차게 잘라 넣었다. 비슷한 항목은 하나로 묶고(기름진 음식, 일찍·푹 자기), 그림 개수에 따라 크기를 바꿔 화면 가운데에 고르게 놓았다.

**⑤ 말풍선과 그림이 겹치지 않게**

```text
마지막 화면에서 또박이의 설명 말풍선과 예시 이미지가 겹쳐져. 전체적으로 말풍선의 크기를 조금 줄여줘. 글씨 크기는 그대로 해줘
```

→ 글씨 크기는 유지하고 말풍선의 여백과 높이만 줄였다. 또박이 목소리가 나오지 않는 기기에서도 화면이 멈추지 않고 넘어가도록 안전장치를 넣었다.

**⑥ 앱 안에서 동작하는 수업**

```text
의료진이 건강검진 확인사항을 누르면 내가 이제 올리려고 하는 교육 동영상이 화면에 나와야 해
```

```text
난 앱 안에서 구동되도록 해야 하는데
```

→ 의료진이 '건강검진 기본 확인사항'을 묶어 발급하면, 환자 홈의 그 카드에서 수업이 앱 화면 안에 열리도록 연결하였다. 앱의 소리 설정을 따르고, 끝까지 보면 '다 봤어요'가 기록되며 다음 안내로 이어진다.

**⑦ 내용과 화면을 나누기**

```text
단순히 우리가 채운 내용이 표시되는 게 아니라 앱 내의 정보를 가지고 저렇게 작성되게끔 할 수 있어?
```

→ 수업의 장면·퀴즈를 데이터 파일 하나로 분리하였다. 수업 화면과 관리자 화면이 같은 파일을 읽어, 내용을 고치면 관리자 화면의 '장면 수·퀴즈 수'도 함께 바뀌도록 설계하였다.

- **AI가 만든 것 / 사람이 고친 것**

AI는 빠르게 초안을 만들고, 간호학과 팀원은 그 초안이 **환자에게 정확하고 안전하게 전달되는지**를 판단해 고쳤다.

| AI가 만든 것 | 사람이 고친 것 |
|---|---|
| 화면 구성과 기본 코드 | 의학 용어를 대상자 눈높이의 쉬운 말로 바꾸었다. |
| 글로만 된 안내문 초안 | 금식, 장정결제 복용, 먹어도 되는 음식처럼 꼭 지켜야 할 핵심 단어를 골라 사진과 그림 카드로 바꾸었다. 글을 읽지 않아도 무엇을 해야 하는지 한눈에 알 수 있게 하였다. |
| 순서대로 나열된 안내문 | 준비 과정을 캐릭터 '또박이'가 설명하는 사진 수업 영상(1~8교시)으로 다시 구성하였다. 환자가 보고 들으며 차례대로 따라 할 수 있게 하였다. |
| 안내문 내용 초안 | 금식 시작 시각, 장정결제 복용량과 시간, 혈압약 복용 예외 등을 간호학 교재 기준으로 검토하여 바로잡았다. |
| 티치백 문항 초안 | "검사 날 새벽 5시 이후 먹어도 되는 것은?"처럼 환자안전과 직결된 항목 중심으로 문항을 다시 구성하였다. |
| 다국어 번역 기능 | 번역 과정에서 시간·용량 숫자가 바뀌면 위험하다고 판단하여, 숫자가 원문과 다르면 번역을 쓰지 않도록 규칙을 추가하였다. |
| 또박이 캐릭터 디자인 | 어르신이 편하게 느끼도록 동그란 눈과 볼터치를 넣고, 유명 캐릭터와 겹치지 않는 자체 캐릭터로 만들었다. |
| 또박이 말투와 목소리 | 말투는 짧은 존댓말로 한 번에 한 가지만 말하게 하였다. 귀여운 목소리 외에 어르신이 알아듣기 쉬운 차분한 목소리를 고를 수 있게 하였다. |

- **결과를 확인한 방법**
  - 안내 내용: 간호학과 팀원이 간호학 교재와 병원 공개 안내문에 대조하여 검토하였다.
  - 사진·그림·영상: 각 장면이 안내문 내용과 일치하는지, 그림만 보고도 같은 뜻으로 이해되는지 직접 확인하였다.
  - 기능: 시연용 계정으로 간호사 코드 발급 → 환자 열람 → 수업 영상 → 티치백 → 결과 확인 흐름을 반복 실행하였다.
  - 자동 검사: 번역 숫자 보존 규칙과 보안 기능은 테스트 코드를 작성해 자동으로 확인하였다.

## 7. 아쉬운 점과 다음에 할 일

**아쉬운 점**
- S.T.A.T는 여러 진료 영역을 한꺼번에 다루기보다, 하나의 교육 과정을 온전히 완성하는 데 우선순위를 두었다. 이에 따라 환자안전과 직결되는 대장내시경 전 준비와 복약 안내를 먼저 구현하고, 안내에서 티치백, 재설명, 결과 확인에 이르는 과정이 끊김 없이 이어지도록 하였다. 다만 수술 전후 안내와 입·퇴원 안내 등 다른 진료 영역까지 담지 못한 점은 아쉬움으로 남는다.
- 실제 사용자인 고령자·장애인·외국인 환자의 의견을 직접 듣는 과정은 다음 단계의 과제로 남겨 두었다. 또한 큰 글씨와 그림 안내로 기본적인 접근성은 갖추었으나, 장애 유형에 맞춘 기능은 반영되지 않았다.
- 다국어 안내는 의미 전달이 가능한 수준까지 구현하였으며, 의료 통역 전문가의 감수를 거쳐 표현의 정확도를 더 높일 여지가 있다.

**다음에 할 일**
1. **진료 영역 확대**: 이번에 완성한 교육 과정을 바탕으로 수술 전후 안내, 입·퇴원 안내 등 다른 진료 영역의 안내문을 차례로 추가한다.
2. **사용자 의견 반영**: 고령자·장애인·외국인 환자가 직접 앱을 사용해 보는 사용성 평가를 진행하고, 그 결과를 화면과 안내 문구 개선에 반영한다.
3. **장애 유형별 기능 추가**
   - 시각장애: 화면 낭독기 호환, 음성 읽어주기(TTS)
   - 청각장애: 수어 영상, 읽는 부분을 강조하는 자막
   - 발달장애·인지 저하: 이지리드(Easy Read) 기준에 맞춘 쉬운 글과 한 화면 한 내용 구성
4. **다국어 안내 감수**: 의료 통역 전문가의 감수를 받아 번역 표현의 정확도를 높인다.
5. **실제 도입 준비**: 테스트용과 운영용 DB를 분리하고 병원 정보보호 기준에 맞춰 보안을 점검한다. 또한 티치백 결과를 모아 환자가 자주 헷갈리는 항목을 분석하고, 이를 병원 안내문 개선에 활용한다.
